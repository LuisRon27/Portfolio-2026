Plataforma web corporativa para el control, búsqueda y reporte de remitos de

Módulo transaccional del ecosistema digital de ONCOMED Reno SA.

================================================================================
3. DESCRIPCIÓN CORTA
================================================================================

Sistema interno para administrar la facturación y liquidación de remitos
(comprobantes de entrega) entre ONCOMED y su red de farmacias asociadas.
Permite buscar comprobantes, marcar como recibidos/liquidados, editar valores
de liquidación en línea, y generar reportes exportables a Excel con filtros
avanzados por fecha, farmacia y estado de liquidación.

================================================================================
4. DESCRIPCIÓN TÉCNICA
================================================================================

Aplicación web monolítica desarrollada en PHP nativo (procedural) con SQL
Server como motor de base de datos. Implementa una arquitectura simple de
tres capas separando lógica de negocio (Class/), presentación (Pages/) y
componentes reutilizables (Components/). El frontend utiliza Bootstrap 5,
jQuery 3.3.1, DataTables 1.11 y SheetJS para exportación a Excel.

La autenticación es por sesión PHP con credenciales almacenadas en base de
datos. El sistema consume datos de cuatro bases de datos SQL Server
interconectadas (Hmoore, envios, interfaz, depo_embalaje) que forman parte
de un ERP hospitalario legacy. Las consultas principales utilizan JOINs
entre bases de datos y una CTE (Common Table Expression) con ROW_NUMBER()
para ranking de productos en reportes avanzados.

La interacción críticia (búsqueda de remitos, actualización de recibido,
edición inline de valores liquidados) se realiza mediante peticiones AJAX
con respuestas JSON y HTML. Incluye manejo de transacciones SQL con
commit/rollback en operaciones de actualización crítica.

5. STORYTELLING
================================================================================

Contexto real:
ONCOMED Reno SA es una empresa farmacéutica argentina que distribuye
medicamentos a una red de farmacias. El proceso de facturación implicaba
que el equipo administrativo revisara manualmente miles de remitos para
determinar cuáles habían sido recibidos por las farmacias y cuáles estaban
pendientes de liquidación económica. No existía una herramienta unificada;
los datos estaban dispersos en múltiples tablas del ERP corporativo
(SQL Server) y el seguimiento se hacía con planillas Excel compartidas.

El problema:
El administrador de farmacias necesitaba: (1) buscar rápidamente un remito
específico sin navegar entre sistemas, (2) poder marcar masivamente los
comprobantes como "recibidos" con su valor liquidado, (3) generar reportes
por rango de fechas, por farmacia y por estado de liquidación, y (4)
exportar esos reportes para conciliación contable.

La solución:
Se desarrolló un sistema web interno (intranet corporativa) que centraliza
la consulta de remitos desde la base de datos transaccional del ERP,
permite la actualización en tiempo real del estado de recibido y valor
liquidado, y ofrece un módulo de reportes con filtros combinados y
exportación a Excel. Todo desde una interfaz limpia con Bootstrap 5.

Mi rol:
Análisis de requerimientos junto al administrador de farmacias, diseño de
la interfaz y experiencia de usuario, desarrollo full-stack del sistema
(PHP + SQL Server + JavaScript), integración con las bases de datos
existentes del ERP corporativo, y despliegue en servidor XAMPP del
datacenter de la empresa.

Resultado:
El sistema se integró al ecosistema digital de ONCOMED, reduciendo el
tiempo de conciliación de remitos de horas a minutos. La administración
farmacéutica ahora cuenta con visibilidad en tiempo real del estado de
sus entregas y valores pendientes de liquidación. El sistema continúa en
producción como parte del portal interno de la compañía.

8. DESAFÍOS Y SOLUCIONES
================================================================================

DESAFÍO 1: Integración con bases de datos legacy del ERP corporativo.
  El ERP de ONCOMED almacena datos críticos en cuatro bases de datos SQL
  Server distintas (Hmoore, envios, interfaz, depo_embalaje). Los remitos
  están en interfaz con JOINs a envios para clientes y proveedores.
  SOLUCIÓN: Consultas cross-database con sintaxis [base].dbo.[tabla] y
  JOINs entre servidores. CTE con ROW_NUMBER() para ranking de productos
  en reportes sin duplicados.

DESAFÍO 2: Edición inline persistente en tabla de reportes.
  El usuario necesitaba modificar el valor liquidado directamente desde
  la tabla de resultados sin formularios ni modales.
  SOLUCIÓN: Implementación de contenteditable + evento onblur + fetch API
  con endpoint POST que devuelve JSON. Experiencia similar a Excel online.

DESAFÍO 3: Búsqueda eficiente sobre tablas transaccionales grandes.
  La tabla remitos_cab contiene miles de registros y la búsqueda debía
  ser instantánea.
  SOLUCIÓN: Búsqueda AJAX con prepared statements y filtros eficientes
  (sucursal=1, estado<>'Anulado', Pagador LIKE '%ONCOMED%'). DataTables
  del lado del cliente con paginación de 10 registros.

DESAFÍO 4: Mantenimiento legacy con estándares modernos.
  El código existente usaba consultas SQL inseguras (inyección) y estilos
  inconsistentes.
  SOLUCIÓN: Migración progresiva a prepared statements en los módulos
  nuevos, estandarización a Bootstrap 5, y separación de responsabilidades
  con estructura de directorios clara.

DESAFÍO 5: Exportación a Excel sin servidor intermedio.
  No se podía instalar librerías PHP en el servidor XAMPP compartido.
  SOLUCIÓN: SheetJS (xlsx) del lado del cliente. La librería genera el
  archivo .xlsx directamente en el navegador a partir de los datos de la
  tabla HTML, eliminando la necesidad de procesamiento en servidor.

16. RECOMENDACIONES DE MEJORA (para entrevista)
================================================================================

Si en una entrevista te preguntan "¿Qué mejorarias?":

1. Hashing de contraseñas (password_hash/password_verify).
2. Migrar a PDO con prepared statements en todo el código.
3. Implementar CSRF tokens en formularios.
4. Escapar salidas HTML con htmlspecialchars().
5. Agregar logging de acciones (quién marcó qué y cuándo).
6. Migrar a un framework moderno (Laravel) o al menos composer.
7. Agregar tests automatizados (PHPUnit).
8. Implementar paginación del lado del servidor en DataTables.
9. Agregar Docker para entorno reproducible.
10. Migrar a SQL Server Auth con Windows Authentication.
11. Implementar soft deletes y auditoría de cambios.
12. Separar frontend con Vue.js o React para la edición inline.

Esto demuestra visión de mejora continua y conciencia de las
debilidades del sistema actual, algo que los entrevistadores valoran.
