TÍTULO PROFESIONAL:
====================
Sistema de Gestión de Depósito Descartable y Soluciones
(Warehouse & Inventory Management System for Medical Supplies)

SUBTÍTULO:
===========
Plataforma web corporativa para la gestión integral del ciclo de solicitud,
autorización, preparación y recepción de insumos descartables y soluciones
hospitalarias — Henry Moore / Oncomed Reno SA

DESCRIPCIÓN CORTA:
===================
Sistema web interno que digitaliza y automatiza el flujo completo de solicitud
de materiales descartables y soluciones para una droguería oncológica. Reemplaza
procesos manuales con un workflow de 4 etapas (Solicitar → Autorizar → Preparar →
Recibir), notificaciones por email, trazabilidad de lotes y reportes de egreso.
Construido en PHP nativo con Bootstrap 5, SQL Server + MySQL, y PHPMailer.

DESCRIPCIÓN TÉCNICA:
=====================
Aplicación web transaccional desarrollada en PHP 7+ procedural, con arquitectura
monolítica de página única por operación. El frontend utiliza Bootstrap 5.3,
jQuery 3.6, Bootstrap Icons y DataTables para tablas interactivas. El backend
opera sobre Microsoft SQL Server (motor principal) con Linked Server a MySQL
(MariaDB) vía OPENQUERY para consultas en tiempo real al sistema legacy de stock
(drugstore). La autenticación es por formulario contra tabla Usuarios con
sesiones PHP nativas. El envío de correos usa PHPMailer con SMTP autenticado.
La seguridad se implementa mediante permisos por usuario-aplicación-acción en
tabla UsuariosAplicaciones. Los reportes se generan en HTML con impresión nativa
y exportación a PDF. La trazabilidad se registra en tablas dedicadas con
timestamp, usuario y dirección IP. El servidor es IIS con SQL Server Native
Client (sqlsrv).

STORYTELLING:
=============
En una droguería oncológica de Buenos Aires, la gestión de insumos descartables
y soluciones se manejaba con planillas, llamadas telefónicas y correos sueltos.
El proceso era propenso a errores, sin trazabilidad ni control de stock en
tiempo real.

Se desarrolló este sistema para digitalizar el flujo completo: el personal
solicita insumos desde un catálogo con stock visible, un supervisor autoriza
(lo que descuenta automáticamente del inventario real en MySQL vía linked
server), el depósito prepara el pedido, y el solicitante confirma recepción.
Cada paso envía notificaciones por email a los actores involucrados.

El resultado: trazabilidad total por lote y vencimiento, reducción de errores,
visibilidad en tiempo real del estado de cada solicitud, y un histórico auditable
con registro de IP y operación. El sistema se convirtió en una herramienta
crítica para la operación diaria, integrada al ecosistema corporativo existente.

FUNCIONALIDADES PRINCIPALES:
============================

 1. SOLICITUD DE ARTÍCULOS DESCARTABLES
    - Catálogo de productos con stock actual en tiempo real (vía Linked Server)
    - Selección de tipo de entrega
    - Validación de stock antes de guardar
    - Límite de solicitudes pendientes por usuario (1 genérica, 3 para esantos)
    - Tabla de detalle con eliminación individual de artículos

 2. SOLICITUD DE SOLUCIONES
    - Similar a descartables pero para soluciones hospitalarias (group_id=8)
    - Flujo independiente con su propia tabla de seguimiento

 3. AUTORIZACIÓN DE SOLICITUDES (Panel de Seguimiento)
    - Dashboard unificado que muestra solicitudes pendientes de ambos tipos
    - Indicadores visuales con semáforo: verde (completado) / rojo (pendiente)
    - Acciones: Autorizar, Preparar, Recibir desde la misma fila
    - Descuento inteligente de stock por lote (FIFO) con OPENQUERY
    - Registro de trazabilidad con lote, vencimiento, remito

 4. PREPARACIÓN DE PEDIDOS
    - Marcar solicitud como preparada con registro de usuario y timestamp
    - Verificación de que la solicitud fue autorizada previamente

 5. RECEPCIÓN DE PEDIDOS
    - El solicitante original confirma la recepción
    - Validación de que solo el creador puede recibir

 6. NOTIFICACIONES POR EMAIL (PHPMailer vía SMTP)
    - Al crear solicitud: aviso a administración, autorizadores y grupo 5
    - Al autorizar: detalle con lote, vencimiento y cantidades aprobadas
    - Recordatorio de recibir: email automático al solicitante con link
    - Recordatorio de preparar: email a preparadores y despachos

 7. MAESTRO DE ARTÍCULOS (CRUD)
    - ABM completo con activos/inactivos, filtro por radio button
    - Campos: UxB, Stock Seguridad, Consumo Mensual
    - Gestión de estado (activo/inactivo)

 8. REPORTES
    - Planilla Técnica de Stock: cruza dos bases de datos (SQL Server + MySQL)
      con fórmulas de reposición automática (30/45/60 días)
    - Reporte de Egreso Descartable: filtro por rango de fechas y usuario
    - Reporte de Egreso Soluciones: similar para soluciones
    - Visualización de detalle por remito con impresión y PDF
    - Listado de Remitos con trazabilidad

 9. TRAZABILIDAD Y AUDITORÍA
    - Tabla TrazabilidadProductos: registra cada ítem entregado con lote,
      fecha de vencimiento, remito y cantidad
    - Tabla TrazaOperacionSistemas: log de cada operación con usuario,
      timestamp, IP, script y consulta SQL ejecutada

10. GESTIÓN DE USUARIOS Y PERMISOS
    - Autenticación contra tabla Usuarios (SQL Server)
    - Permisos granulares por usuario-aplicación-opción (UsuariosAplicaciones)
    - Roles inferidos: Solicitante, Autorizador, Preparador, Administrador

ARQUITECTURA:
=============
Tipo: Monolítica procedural (sin framework)
Patrón: Page Controller (cada PHP es una página que maneja su propia request)
Frontend: Server-side rendering con HTML embedido en PHP
Flujo de datos: Form → POST → PHP class → SQL Server → redirect → GET page
Base de datos híbrida: SQL Server como oráculo central + Linked Server a MySQL
  para consultas de stock en tiempo real

El patrón de diseño es "página como controlador": cada archivo .php recibe
parámetros (GET o POST), procesa lógica de negocio, e incluye HTML para
renderizar resultado o redirige a otra página. No hay separación MVC; la capa
de presentación y negocio conviven en el mismo archivo.

==========================
⚠️ Vulnerabilidades detectadas (propias de un sistema legacy interno):
  - SQL Injection directa en casi todas las consultas (variables interpoladas)
  - Contraseñas en texto plano (SELECT Pass FROM Usuarios WHERE...)
  - Credenciales de base de datos en texto plano en archivos PHP
  - Sin prepared statements ni consultas parametrizadas
  - Sin validación CSRF en formularios
  - Sin escape de output (XSS potencial)
  - Sin hashing de contraseñas
  - Sesiones sin timeout forzoso
  - Exposición de IP interna y estructura de tablas en comentarios

✅ Aspectos positivos:
  - Permisos granulares por aplicación/opción por usuario
  - Trazabilidad completa de operaciones con IP, usuario y timestamp
  - Validación de permisos en cada página sensible
  - Control de stock en tiempo real antes de autorizar
  - Transacción begin/commit en descuento de stock (aunque comentado)

DESAFÍOS TÉCNICOS Y SOLUCIONES:
================================
Desafío 1: Stock en dos bases de datos distintas (SQL Server + MySQL)
  Solución: Linked Server con OPENQUERY para consultar MySQL desde SQL Server
  en tiempo real, evitando duplicación de datos.

Desafío 2: Descontar stock por lote respetando FIFO
  Solución: Algoritmo que itera sobre cada lote (batch) del producto,
  descuenta la cantidad aprobada del lote más antiguo primero, y continúa
  con el siguiente si es necesario. Registra cada operación en
  TrazabilidadProductos con lote y vencimiento.

Desafío 3: Notificaciones en cada etapa del workflow
  Solución: PHPMailer con SMTP autenticado, destinatarios dinámicos según
  la etapa (autorizadores, preparadores, solicitante) con consultas a tablas
  de grupos y usuarios.

Desafío 4: Límite de solicitudes pendientes por usuario
  Solución: Validación previa a mostrar el formulario que consulta solicitudes
  no recibidas. Lógica especial para el usuario "esantos" (límite=3).

RESUMEN CASE STUDY:
====================
Título: Digitalización del Workflow de Insumos Descartables

Cliente: Oncomed Reno SA / Henry Moore — Droguería Oncológica, CABA

Problema: La gestión de insumos descartables y soluciones se realizaba
con planillas, llamadas y correos sueltos. No había trazabilidad, el
stock se consultaba en sistemas separados, y los pedidos se perdían.

Solución: Sistema web transaccional con workflow de 4 etapas, integración
SQL Server ↔ MySQL en tiempo real, notificaciones por email en cada paso,
dashboard de seguimiento con indicadores visuales, y trazabilidad completa
con auditoría de operaciones.

Tecnologías: PHP, Bootstrap 5, jQuery, DataTables, SQL Server,
MySQL (Linked Server), PHPMailer, IIS

Resultados:
• Trazabilidad total de cada insumo desde solicitud hasta recepción
• Stock consultado en tiempo real sin duplicación de datos
• Reducción de pedidos perdidos gracias a recordatorios automáticos
• Visibilidad completa del estado de cada solicitud para todos los actores
• Historial auditable con registro de IP, usuario y operación
• Herramienta crítica en producción, usada diariamente

Mi rol: Desarrollo full stack completo — análisis, diseño de BD,
frontend, backend, integración, testing y puesta en producción.
