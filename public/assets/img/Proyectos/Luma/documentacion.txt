================================================================================
2. DESCRIPCIÓN TÉCNICA (para fichas de proyecto)
================================================================================

Proyecto web frontend 100% estático que funciona como sitio corporativo 
completo para una agencia de servicios digitales. Arquitectura SPA-like 
sobre una landing page principal con navegación por anclas (#home, #services, 
#portfolio, #about, #contact), complementada con 12+ páginas secundarias 
organizadas en subdirectorios: servicios (4), portafolio (5 casos), blog 
(2 artículos), calculadora interactiva y página de agradecimiento.

El sitio opera sin backend — el formulario de contacto se integra con 
FormSubmit.co como servicio externo de email. El tracking se realiza 
mediante Meta Pixel (Facebook Ads). El despliegue se hace en Netlify 
con HTTPS automático, y la indexación SEO está optimizada con sitemap.xml, 
robots.txt, Open Graph, Twitter Cards y meta tags completos.

Sistema de diseño propio definido en CSS con 32+ variables personalizadas 
(colores violeta/amarillo, sombras, radios, transiciones con cubic-bezier), 
organizado en 12+ módulos numerados (variables, reset, tipografía, 
componentes, secciones, responsive, animaciones). JavaScript vanilla con 
patrón módulo (objeto CONFIG + Utils con throttle/debounce/isValidEmail + 
init* functions + initAll orchestrator). Sin frameworks JS ni bundlers.

Incluye una calculadora de presupuestos de Community Manager hecha en 
JavaScript puro que estima costos en ARS según cantidad de redes sociales, 
publicaciones, historias, reels y diseño, con actualización en tiempo real 
del precio total.

8. SEGURIDAD
================================================================================

  • HTTPS forzado por Netlify (TLS automático)
  • Sin backend ni base de datos → sin superficie de ataque server-side
  • Sin dependencias npm → sin riesgos de supply chain
  • Sin autenticación ni sesiones → sin riesgo de account takeover
  • Formulario delegado a FormSubmit.co → sin procesar datos sensibles
  • Meta Pixel con protocolo HTTPS → tracking seguro

  OBSERVACIONES:
  • CAPTCHA deshabilitado en FormSubmit (_captcha = false) → riesgo de spam
    (inferencia: decisión consciente por UX, pero mejorable)
  • Email visible en código fuente → potencial spam harvesting
  • Sin Content Security Policy (CSP) explícita

================================================================================
9. PERFORMANCE
================================================================================

  • 100% estático → sin tiempo de renderizado server-side
  • Preload de CSS crítico (Bootstrap, Google Fonts) → LCP reducido
  • Lazy loading en imágenes de portafolio y blog
  • Sin frameworks JS pesados (no React, no Vue, no Angular)
  • Imágenes en WebP → ~30% menos peso que PNG/JPG
  • CSS sin @import (todo link directo) → sin render blocking en cadena
  • Throttle/debounce en handlers de scroll → sin jank en móviles
  • Animaciones con IntersectionObserver (no scroll events) → GPU aceleradas
  • Tipografía fluida con clamp() → sin saltos de layout en responsive
  • Sin fuentes auto-cargadas → FOIT controlado con preload

  OPORTUNIDADES DE MEJORA:
  • Minificar CSS (~7,237 líneas → ~50% reducción potencial)
  • Minificar JS (389 líneas → ~40% reducción)
  • Implementar srcset en imágenes hero para resolución adaptativa
  • Convertir a WebP también imágenes de portafolio (algunas en PNG)
  • Añadir service worker para caching offline parcial
  • Unificar CSS específicos de página para reducir requests

  ÁREAS DE MEJORA (con mirada senior):
  • Duplicación de HTML: navbar y footer repetidos en cada página.
    Solución senior: Static Site Generator (Astro, 11ty, Hugo) o
    Server-Side Includes (SSI) en Netlify.
  • Sin minificación: ~7,200 líneas de CSS y ~390 de JS sin comprimir.
    Solución: PostCSS + Terser en build step mínimo.
  • Sin testing: ni siquiera linting. Solución: HTMLHint + StyleLint +
    ESLint en pre-commit hook.
  • CAPTCHA deshabilitado en formulario. Solución: habilitar _captcha 
    en FormSubmit o migrar a Netlify Forms + reCAPTCHA.
  • Sin manejo de errores server-side en formulario (todo confía en 
    FormSubmit). Solución: función serverless en Netlify Functions.
  • Sin i18n: solo español. Si la agencia crece, necesitará inglés/portugués.

  NOTA FINAL:
  Este es un proyecto SÓLIDO para el nivel que representa. Muestra 
  maestría en los fundamentos de la web (HTML, CSS, JS vanilla) y 
  criterio para elegir las herramientas adecuadas. Donde otros pondrían 
  React + Next.js + Tailwind + Vercel para un sitio que bien podría 
  servirse con HTML estático, aquí se eligió simplicidad y performance.
