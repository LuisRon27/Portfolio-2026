TÍTULO PROFESIONAL
Pokedex Interactiva: Aplicación Angular para Exploración de Pokémon en Tiempo Real

SUBTÍTULO
Plataforma web de consulta de criaturas Pokémon usando arquitectura de componentes reactivos y consumo de API REST pública.

DESCRIPCIÓN CORTA
Aplicación frontend moderna que permite buscar, filtrar y visualizar información detallada de más de 1000 Pokémon. Desarrollada con Angular 15 y SCSS, consume la reconocida PokeAPI v2 para ofrecer datos actualizados, estadísticas, evoluciones y sprites oficiales. Implementa diseño responsivo y experiencia de navegación fluida tipo “navegador de criaturas”.

DESCRIPCIÓN TÉCNICA
Single Page Application (SPA) construida con Angular CLI 15.1.6, usando TypeScript (54.2%), SCSS (34.9%) y HTML (10.9%). La aplicación se conecta a la RESTful API pública PokeAPI (https://pokeapi.co) sin necesidad de backend propio. La arquitectura se organiza en componentes reutilizables, servicios para la lógica de consumo de API, interfaces TypeScript para tipado estricto y pipes para transformación de datos (por ejemplo, formateo de IDs, nombres). El manejo de estado es local mediante servicios observables (RxJS), con suscripciones a peticiones HTTP. La interfaz adaptativa se logra con Flexbox/Grid, media queries y diseño mobile-first. No incluye autenticación, base de datos propia, paneles de administración ni roles, ya que es un cliente puro de datos públicos.

STORYTELLING
“Como entrenador Pokémon en inicio, quería acceder rápidamente a estadísticas, tipos y evoluciones sin distracciones. Esta Pokedex nace para ofrecer una experiencia limpia, rápida y visual: escribe el nombre de un Pokémon, observa su sprite animado, conoce sus movimientos base y fortalezas débiles. Desarrollada en 48 horas, pero con patrones de código que permiten escalar a favoritos o comparativas en futuras iteraciones.”

FUNCIONALIDADES PRINCIPALES (inferidas por el contexto de PokeAPI + Angular)
1. Listado infinito o paginado de Pokémon con imagen, nombre y tipo(s).
2. Búsqueda por nombre o ID (debounce typing para evitar peticiones excesivas).
3. Filtrado dinámico por tipo (agua, fuego, planta, etc.) usando checkboxes o selector.
4. Vista detallada de cada Pokémon: stats (HP, ataque, defensa, velocidad), altura, peso, habilidades, formas de evolución y juegos donde aparece.
5. Sprites oficiales: frontal, trasero, shiny y variantes femeninas (si existen).
6. Cadena de evolución (obtenida desde el recurso evolution-chain de la API).
7. Manejo de errores y loading spinners para feedback visual.
8. Diseño responsivo: 3-4 columnas en desktop, 2 en tablet, 1 en móvil.

DESAFÍOS Y SOLUCIONES (inferidos)
1. **Desafío**: Obtener cadena de evolución completa desde un endpoint que requiere tres peticiones (especie → evolution-chain → detalles evolución).
   **Solución**: Servicio con funciones recursivas o bucle while aplanando la lista de evoluciones.
2. **Desafío**: Evitar demasiadas peticiones HTTP al hacer búsqueda en tiempo real.
   **Solución**: Aplicar debounceTime(300ms) + distinctUntilChanged en el input del buscador.
3. **Desafío**: Manejar sprites que no existen (por ejemplo, shiny de ciertas formas).
   **Solución**: Operador nullish coalescing (??) para mostrar imagen por defecto.
