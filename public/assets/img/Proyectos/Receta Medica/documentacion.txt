TÍTULO PROFESIONAL
==================
Sistema de Gestión de Recetas Médicas Digitales (Full-Stack)

SUBTÍTULO
=========
Plataforma enterprise de prescripción electrónica con flujos de autorización,
generación de documentos oncológicos (FPO), integración con APIs externas
(RCTA/OSECAC) y notificaciones multicanal (email + WhatsApp).

DESCRIPCIÓN CORTA
=================
Sistema web profesional para la gestión integral del ciclo de vida de recetas
médicas digitales. Cubre desde la prescripción por parte del médico, pasando
por la autorización de auditoría y control de secretaría, hasta la dispensación
en farmacia. Soporta dos instituciones de salud (HM y WO) con flujos
diferenciados, integración con APIs gubernamentales (OSECAC), generación
automática de Formularios de Prescripción Oncológica (FPO) en PDF, y
notificaciones al paciente vía email y WhatsApp.

DESCRIPCIÓN TÉCNICA
===================
Aplicación full-stack enterprise construida con Angular 21 (frontend SPA) y
ASP.NET Core 10 Web API (backend). Arquitectura N-Tier con capas de
Controllers, Services y DbContexts sobre SQL Server. Autenticación mediante
JWT Bearer con políticas de autorización basadas en claims y roles (permisos
granulares: Sistema, Secretaria, Farmacia, Auditoria, Medicos). Consume dos
bases de datos SQL Server (Hmoore y AgendaWO) a través de Entity Framework
Core 10 con dos DbContexts independientes. Integración con tres APIs
externas: RCTA (catálogo de medicamentos y validación de recetas), OSECAC
(prescripciones gubernamentales con autenticación OAuth2) y Chattigo
(notificaciones WhatsApp mediante HSM). Generación de PDFs con QuestPDF y
manejo de documentos oncológicos (FPO) con iText. Notificaciones por correo
electrónico vía SMTP con servidor dedicado. Almacenamiento de PDFs en
recursos compartidos UNC (red interna). Logger centralizado en base de datos
con middleware de captura de excepciones. Frontend con Bootstrap 5, diseño
responsive, formularios reactivos y template-driven, interceptores HTTP
funcionales, guards de ruta, y detección de cambios con Zone.js event
coalescing.

STORYTELLING
============
En el ecosistema de salud privada, la prescripción médica tradicional en papel
genera ineficiencias: pérdida de recetas, ilegibilidad, falta de trazabilidad,
demoras en autorizaciones y problemas de adherencia al vademécum. Dos
importantes instituciones de salud (Henry Moore y William Osler) necesitaban
una solución unificada pero flexible que respetara sus flujos de trabajo
particulares.

Receta Digital nació como respuesta a esta necesidad. El desafío técnico era
significativo: integrar dos sistemas legacy con esquemas de base de datos
similares pero no idénticos, conectar con APIs gubernamentales de
prescripción electrónica (OSECAC), implementar un clasificador inteligente de
medicamentos (extracápita, cápita, alto costo, PPG) y generar documentos
oncológicos reglamentarios (FPO) en formato PDF, todo mientras se mantenían
flujos de autorización multi-rol (médico → auditor → secretaría → farmacia).

El resultado es una plataforma robusta que gestiona cientos de recetas
digitales diarias con trazabilidad completa, notificaciones automáticas al
paciente, integración con el sistema de dispensación farmacéutica externo
(RCTA), y cumplimiento regulatorio para recetas oncológicas y de alto costo
(submitidas a OSECAC). La aplicación maneja la clasificación automática de
medicamentos según el tipo de cobertura de cada paciente y obra social,
optimizando el proceso de autorización y reduciendo el tiempo de espera del
paciente de días a minutos.

FUNCIONALIDADES PRINCIPALES
===========================

□ AUTENTICACIÓN Y SEGURIDAD
  - Login unificado contra dos bases de datos (HM y WO)
  - JWT con claims personalizados (permisos, rol, tipoUsuario)
  - Política de autorización "RecetaAccess" con 5 niveles de permiso
  - Token con expiración de 30 días y renovación implícita

□ PRESCRIPCIÓN MÉDICA
  - Búsqueda de paciente por DNI/HC con datos demográficos y de cobertura
  - Búsqueda de medicamentos con paginación contra API externa RCTA
  - Clasificación automática del medicamento (Extracápita, Cápita,
    No Oncológico, Alto Costo, PPG) según la entidad del paciente
  - Receta multicobertura y multiproducto
  - Validación de fechas de emisión y vencimiento
  - Firma digital del médico (canvas HTML5)

□ FLUJO DE AUTORIZACIÓN (AUDITORÍA)
  - Panel de recetas pendientes con filtros por documento y fecha
  - Autorización/rechazo con mensaje personalizado
  - Reemisión y reenvío de recetas
  - Control separado para HM, WO y OSECAC

□ CONTROL DE SECRETARÍA
  - Dashboard de recetas realizadas con filtros avanzados
  - Control administrativo con observaciones
  - Exportación a Excel de todas las recetas
  - Anulación de recetas OSECAC

□ FORMULARIO DE PRESCRIPCIÓN ONCOLÓGICA (FPO)
  - Formulario reactivo completo con datos del paciente, diagnóstico OMS,
    estadificación TNM, tratamientos previos (cirugía, quimioterapia,
    hormonoterapia, inmunoterapia, radioterapia)
  - Listado dinámico de medicamentos oncológicos
  - Generación de PDF con formato reglamentario
  - Cálculo automático de superficie corporal
  - Soporte para OSDEPYM y otras obras sociales

□ NOTIFICACIONES MULTICANAL
  - Envío automático de link de receta por email (SMTP con plantillas HTML)
  - Notificaciones WhatsApp mediante Chattigo API (mensajes HSM)
  - Notificaciones diferenciadas por tipo de receta y OS

□ HISTORIAL Y BÚSQUEDA
  - Búsqueda de recetas por tipo y número de documento
  - Visualización del ciclo de vida completo de cada receta
  - Reimpresión y reenvío de recetas históricas

□ PERFIL DEL MÉDICO
  - Edición de datos profesionales (nombre, matrícula, CUIL)
  - Captura de firma digital con canvas
  - Visualización de recetas pendientes de FPO

□ GESTIÓN DE ERRORES Y LOGGING
  - Middleware global de captura de excepciones
  - Logging estructurado en base de datos (LogsSistema)
  - Endpoints de prueba para validar manejo de errores

FLUJO DE UNA RECETA (Caso Completo)
====================================

  1. Médico se autentica (JWT con permisos + tipoUsuario)
  2. Busca paciente por DNI → datos demográficos + cobertura + OOSS
  3. Busca medicamentos (debounced search contra API RCTA)
  4. Selecciona medicamento + dosis + diagnóstico
  5. Sistema clasifica automáticamente:
     - ¿Está en DrogasXentidad del paciente? → EXTRACÁPITA
     - ¿Está en Drogas generales? → CÁPITA
     - ¿Es "interferon alfa 2b"? → CÁPITA (regla especial)
     - Si no: → NO ONCOLÓGICO
     - Para WO: DacxPatologia → ALTO COSTO / PPG
  6. Médico firma digitalmente (canvas) y emite
  7. Backend llama a RCTA → crea receta → obtiene hash + link
  8. Si OSECAC → llama a API OSECAC → genera PDF → guarda en UNC
  9. Envía notificaciones: email (link) + WhatsApp (HSM)
  10. Auditor revisa en panel → autoriza o rechaza (con motivo)
  11. Secretaría controla administrativamente → agrega observaciones
  12. Farmacia dispensa (externo, vía RCTA)
  13. Si oncología → médico genera FPO complementario

DESAFÍOS Y SOLUCIONES
======================

DESAFÍO 1: Integración con sistemas legacy (2 bases de datos)
▸ Solución: Dos DbContexts independientes (DBHmoore y DBWilliamOsler)
  con modelos que reflejan esquemas existentes. Interfaz IUsuario común
  para abstraer diferencias entre HM y WO. Lógica de autenticación
  con failover: primero HM → si no encuentra → WO.

DESAFÍO 2: Clasificación inteligente de medicamentos
▸ Solución: Algoritmo de clasificación multi-nivel que evalúa la
  pertenencia del medicamento a listas de alto costo, extracápita,
  cápita y PPG, considerando la entidad/obra social del paciente.
  Reglas especiales hardcodeadas para casos particulares (interferón).
  La clasificación determina el flujo de autorización completo.

DESAFÍO 3: Integración con API gubernamental OSECAC
▸ Solución: Servicio especializado (RecetaOsecacService) que maneja
  autenticación OAuth2 contra OSECAC, genera PDFs con formato
  oficial, los almacena en recurso compartido UNC, y gestiona
  anulaciones. Manejo de errores con retry lógica y logging.

DESAFÍO 4: Generación de documentos oncológicos (FPO) en PDF
▸ Solución: Servicio FpoService (~1142 líneas) que construye el PDF
  completo con QuestPDF, incluyendo datos del paciente, diagnóstico
  OMS, estadificación, tratamientos previos, esquema solicitado,
  y medicamentos oncológicos con dosis y frecuencia. Formato
  reglamentario con firma y sello del médico.

DESAFÍO 5: Notificaciones multicanal confiables
▸ Solución: Integración con SMTP para email con HTML templates y
  Chattigo API para WhatsApp con mensajes HSM (Highly Structured
  Messages). Manejo de errores de envío con logging. URLs de
  seguimiento incluidas en las notificaciones.

DESAFÍO 6: Manejo de dos identidades visuales (HM y WO)
▸ Solución: Tema dinámico en frontend mediante CSS custom properties
  que se actualizan al login según tipousuario:
  - HM: Dorado (#d9ad27) + Púrpura (#685783)
  - WO: Naranja (#f15a29) + Púrpura (#5d2a86)

DESAFÍO 7: Firma digital del médico sin hardware especializado
▸ Solución: Canvas HTML5 nativo para captura de firma manuscrita.
  Se almacena como string base64 en la BD. Sin dependencia de
  librerías externas (signature_pad instalado pero no usado).

DIFERENCIADORES
===============

★ Multi-institución: Soporte nativo para dos instituciones con
  esquemas de BD similares pero no idénticos, temas visuales
  diferenciados y flujos de autorización personalizados.

★ Clasificación automática: Algoritmo propietario que determina
  el tipo de receta (Extracápita, Cápita, Alto Costo, PPG, No
  Oncológico) basado en el medicamento, la entidad del paciente
  y reglas de negocio específicas.

★ Integración OSECAC: Conexión directa con el sistema oficial
  de prescripciones del gobierno para recetas oncológicas,
  con generación y almacenamiento automático de PDFs.

★ FPO completo: Formulario de Prescripción Oncológica con 36+
  campos, diagnóstico OMS, estadificación TNM, tratamientos
  previos, y medicamentos oncológicos en formato reglamentario.

★ Notificaciones multicanal: Email + WhatsApp con mensajes HSM
  estructurados y links de seguimiento personalizados.

★ Trazabilidad total: Cada acción (emisión, autorización, rechazo,
  control) queda registrada con usuario y timestamp.

★ Sin dependencia de frameworks UI pesados: Bootstrap 5 + CSS
  custom, sin Angular Material, PrimeNG, o ngx-bootstrap.

★ .NET 10 + Angular 21: Stack tecnológico de última generación
  con las versiones más recientes disponibles.
