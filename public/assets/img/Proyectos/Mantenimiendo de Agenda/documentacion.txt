────────────────────────────────────────────────────────────────────────────────
3. DESCRIPCIÓN CORTA
────────────────────────────────────────────────────────────────────────────────

Aplicación web full-stack para la gestión completa de agendas médicas del
Instituto William Osler. Permite a secretarias administrar profesionales,
esquemas de agenda semanal, turnos (CRUD, búsqueda, cambios de estado masivos),
apertura mensual automatizada, feriados, consultorios y especialidades. Incluye
autenticación JWT con políticas de autorización por roles, panel administrativo,
notificaciones por email y soporte PWA con modo offline.

────────────────────────────────────────────────────────────────────────────────
4. DESCRIPCIÓN TÉCNICA
────────────────────────────────────────────────────────────────────────────────

ARQUITECTURA FULL-STACK MONOLÍTICA MODERNA

  Backend (API REST):
  - .NET 10.0 Web API con Entity Framework Core 10 + SQL Server
  - Arquitectura en capas: Controllers → Services → DbContext (Fluent API)
  - Patrón Repository/Service con interfaces y desacoplamiento total
  - JWT Bearer Authentication con políticas de claims (MantenimientoAgenda,
    MedicoAgenda)
  - ApiResponse<T> como envelope unificado para todas las respuestas
  - Middleware personalizado: ExceptionLoggingMiddleware,
    RequestBodyBufferingMiddleware
  - Background Jobs (IHostedService): apertura automática mensual de agendas
    y recordatorios por email
  - Logging estructurado con Serilog (archivo rotativo + consola)
  - Documentación OpenAPI con Scalar UI
  - SMTP para notificaciones por correo electrónico
  - Integración con Active Directory para autenticación de usuarios

  Frontend (SPA):
  - React 19 + TypeScript + Vite 6 con Hot Module Replacement
  - Hash Router para compatibilidad con IIS sin URL rewriting
  - Tailwind CSS 4 + shadcn/ui + 26 componentes primitivos Radix UI
  - Redux Toolkit (5 slices: auth, profesionales, tipoTurnos, consultorios,
    turnos) para estado global
  - TanStack React Query para cache y sincronización de datos del servidor
  - react-hook-form + Zod para validación de formularios tipada
  - Axios con interceptors (JWT automático + chequeo de versión)
  - PWA con vite-plugin-pwa, service worker y manifest icons
  - Modo oscuro nativo con next-themes + Tailwind darkMode class
  - Sonner para notificaciones toast modernas
  - date-fns + react-day-picker para calendarios y manejo de fechas
  - Patrón Clase Service → Repository → Http (Axios) en frontend

  Base de datos:
  - SQL Server (192.168.0.224, base AgendaWO)
  - 18+ entidades modeladas con Fluent API: Turno, Profesional, Especialidad,
    Consultorio, TipoTurno, EstadosTurno, Agenda (esquema semanal), Feriado,
    Usuario, UsuariosAplicacion, Acceso, LogsSistema, LogTurno, Servicio,
    CatLaborale
  - Relaciones M:N (Profesionales <-> Especialidades)
  - Claves compuestas, índices, precisión decimal, campos requeridos

5. STORYTELLING
────────────────────────────────────────────────────────────────────────────────

"El Instituto William Osler, una institución médica de primer nivel, enfrentaba
un desafío crítico: la gestión de agendas médicas se realizaba de forma manual,
con procesos descentralizados que generaban errores, dobles turnos, falta de
visibilidad y una carga operativa enorme para el área de recepción.

Se necesitaba una solución que centralizara la administración de más de 100
profesionales, sus especialidades, consultorios y tipos de atención, permitiendo
a las secretarias abrir agendas mensuales de forma masiva, modificar estados
de turnos en lote, y mantener un control férreo sobre quién accede a qué.

El proyecto 'Agenda Secretaria WO' nació como una plataforma full-stack
moderna, con un backend robusto en .NET 10 y un frontend reactivo en React 19.
Desde el login con Active Directory hasta la apertura automática de agendas
vía background jobs, cada funcionalidad fue diseñada pensando en reducir la
fricción operativa y eliminar el error humano.

Hoy, el sistema maneja la totalidad de las agendas del instituto con
notificaciones por email, control de acceso basado en claims, actualización
en caliente vía PWA y un panel administrativo completo que permite desde
definir feriados hasta cambiar el estado de cientos de turnos en un clic."

6. FUNCIONALIDADES PRINCIPALES
────────────────────────────────────────────────────────────────────────────────

GESTIÓN DE PROFESIONALES
  - CRUD completo con paginación, búsqueda por nombre, activar/inactivar
  - Configuración de título (Dr./Dra.), CUIL, documento, matrícula, teléfono
  - Asignación múltiple de especialidades con tabla de selección
  - Duración de turno configurable (15/20/30/60 min)
  - Fecha de baja programada que bloquea turnos futuros
  - Notificación por email al inactivar un profesional

ESQUEMA DE AGENDA (Agenda Templates)
  - Creación de plantillas semanales por profesional
  - Días de la semana configurables (lunes a domingo)
  - Horario de inicio/fin, duración, especialidad, consultorio, tipo de turno
  - Flag activo/inactivo para deshabilitar sin eliminar

APERTURA DE AGENDA
  - Apertura masiva seleccionando múltiples profesionales y rango de fechas
  - Apertura automática mensual via background job (AperturaAgendaMensualJob)
  - Recordatorio automático de apertura (RecordatorioAperturaAgendaMensualJob)
  - Notificaciones por email de resultados

TURNOS
  - Búsqueda por profesional + rango de fechas
  - Visualización tipo listado con datos: profesional, día, fecha, hora, tipo,
    especialidad, consultorio, estado (con badges de colores)
  - Estados: Libre, Citado, Atendido, Ausente, Bloqueado
  - Registro de hora de llegada, ingreso y salida

MODIFICACIÓN MASIVA DE AGENDA
  - Cambio de estado masivo: seleccionar profesionales + rango fechas +
    nuevo estado
  - Eliminación masiva por tipo de turno + rango fechas
  - Operaciones transaccionales con rollback en caso de error

FERIADOS
  - Calendario visual con date-fns + react-day-picker
  - CRUD completo con indicación de día completo / mañana / tarde
  - Filtro por rango de fechas

CONSULTORIOS Y ESPECIALIDADES
  - CRUD completo con diálogos modales (shadcn Dialog)
  - Tabla de listado con paginación

ADMINISTRACIÓN DE USUARIOS
  - Gestión de usuarios con búsqueda
  - Asignación de permisos por aplicación ("Agenda WO")
  - Filtro por categoría laboral (Médico Asistencial, Recepción, etc.)
  - Claims de permisos mapeados como policies de autorización

SEGURIDAD Y AUTENTICACIÓN
  - Login con Active Directory + SQL Server (doble validación)
  - JWT con expiración configurable (30 días en cookie)
  - Políticas de autorización por claim: "MantenimientoAgenda", "MedicoAgenda"
  - Middleware de errores 401/403 con respuesta JSON personalizada
  - Exception Logging Middleware global
  - Logs de acceso y auditoría (Acceso.cs, LogsSistema.cs, LogTurno.cs)

PWA Y VERSIONADO
  - Service Worker con actualización automática
  - Version checking automático en cada request API
  - Mismatch de versión → reload forzado de aplicación

PANEL / DASHBOARD
  - Sidebar de navegación con iconos Lucide
  - Layout con SidebarProvider, separador y Toaster global
  - Precarga de tipoTurnos y consultorios al montar el dashboard

9. PATRONES Y BUENAS PRÁCTICAS
────────────────────────────────────────────────────────────────────────────────

ARQUITECTÓNICOS
  - Repository Pattern: abstracción de acceso a datos con interfaces
  - Service Layer Pattern: lógica de negocio desacoplada de controladores
  - Dependency Injection nativa de .NET (AddScoped para todos los servicios)
  - ApiResponse<T> Envelope Pattern: respuesta unificada exitosa/error
  - Feature-based modules en frontend (cada funcionalidad es un módulo)

CÓDIGO
  - C# moderno: nullable enabled, records, expression-bodied members
  - TypeScript estricto: tipos genéricos, interfaces explícitas
  - Fluent API de EF Core para configuración de entidades (no data annotations)
  - Zod schemas para validación tipada en frontend y backend
  - DTOs separados de entidades de dominio (no exponer modelos internos)

FRONTEND
  - Componentes pequeños y desacoplados (BuscarTurnos + ListTurnos separados)
  - Custom hooks para lógica reutilizable (useEspecialidades, useTipoTurnos, etc.)
  - Redux Toolkit para estado global compartido (auth, turnos)
  - React Query para estado del servidor (caching, refetch automático)
  - Hash Router para evitar problemas con IIS
  - Service + Repository pattern del lado del cliente (testable)

SEGURIDAD
  - JWT con claims políticas en lugar de roles simples
  - Cookie para token (más seguro que localStorage)
  - Interceptor que omite token en endpoints de autenticación
  - CORS abierto pero controlado por IIS
  - Version checking evita usar clientes desactualizados

ERROR HANDLING
  - Global Exception Middleware con logging Serilog
  - Middleware 401/403 con respuesta JSON consistente
  - Envelope ApiResponse<T> con campo Success y Errors
  - Toast notifications (Sonner) en el frontend

PROBLEMA:
Gestión manual y descentralizada de agendas médicas generando errores,
dobles turnos y sobrecarga operativa en recepción.

SOLUCIÓN:
Plataforma full-stack web con backend .NET 10 y frontend React 19 que
centraliza la administración de profesionales, turnos, agendas, consultorios,
especialidades y feriados con control de acceso basado en roles.

TECNOLOGÍAS:
.NET 10 | React 19 | TypeScript | SQL Server | Entity Framework Core | JWT |
Redux Toolkit | TanStack React Query | shadcn/ui | Tailwind CSS 4 | PWA

LOGROS:
- Automatización de apertura mensual de agendas (background jobs)
- Operaciones masivas transaccionales sobre cientos de turnos
- Autenticación enterprise con AD + JWT + claims policies
- PWA con actualización automática y version checking
- 0 errores de integridad de datos gracias a operaciones atómicas
- UX moderna con modo oscuro, responsive y notificaciones toast

MI ROL:
Full-Stack Developer — Diseño de arquitectura, modelado de base de datos,
desarrollo backend (API REST, seguridad, jobs), desarrollo frontend (SPA,
componentes, estado global, PWA), despliegue en IIS corporativo.
